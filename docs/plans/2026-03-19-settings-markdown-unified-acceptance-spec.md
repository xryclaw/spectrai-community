# 设置页与 Markdown 统一验收标准（可执行）

- 文档版本：v1.0
- 日期：2026-03-19
- 适用范围：`UnifiedSettingsModal`（升级为全屏设置页）与会话 `MessageBubble` Markdown 渲染
- 目标：给前端与 QA 提供“可直接验收”的统一标准，避免抽象描述

## 1. 全屏设置页交互规范（前端实现口径）

### 1.1 页面结构（必须满足）

1. 设置入口点击后，展示全屏设置页（非居中小弹窗）：
- 容器占满视口：`width=100vw`、`height=100vh`
- 页面层级高于常规业务面板，低于系统级强提醒弹层

2. 固定三段式布局：
- 顶部 Header（固定）：标题、返回/关闭、全局状态提示
- 左侧导航（固定）：一级分类 Tab（通用/主题/工作区/MCP/技能/日志）
- 右侧内容区（可滚动）：具体设置表单与状态

3. 滚动行为：
- 仅右侧内容区滚动，Header 和左侧导航不随滚动抖动

### 1.2 交互行为（必须满足）

1. 打开行为：
- 默认落在 `general`
- 若带 `initialTab`，必须准确定位到指定 Tab

2. 关闭行为：
- 点击右上角关闭按钮关闭
- `Esc` 关闭（存在未保存改动时先弹确认）
- 点击蒙层不关闭（防误触）

3. Tab 切换：
- 切换时保留各 Tab 本地未提交输入（如代理 host/port）
- 切换后焦点落在内容区首个可交互控件

4. 保存行为：
- 单项即时保存（Switch）显示轻量成功反馈（Toast 或行内状态）
- 表单类保存（代理配置）使用显式“保存”按钮
- 保存期间禁用重复点击，按钮进入 loading 状态

### 1.3 状态模型（每个 Tab 必须覆盖）

1. `loading`：数据加载中，显示骨架屏或 loading 行
2. `empty`：加载成功但无数据，显示空态文案 + 主行动按钮
3. `error`：请求失败，显示错误文案 + 重试按钮
4. `ready`：正常可交互

## 2. 设置页错误态/空态/加载态文案（统一文案库）

> 文案规则：一句说明问题 + 一句建议动作；避免技术黑话。

### 2.1 全局通用

1. 加载态（全局）
- 文案：`正在加载设置…`
- 判定：进入页面后 100ms 内出现；数据返回后消失

2. 空态（全局）
- 文案：`暂无可配置项`
- 辅助：`请检查当前版本或切换其他设置分类`
- 主按钮：`返回通用设置`
- 判定：后端返回空配置集合时出现

3. 错误态（全局）
- 文案：`设置加载失败`
- 辅助：`请检查网络或服务状态后重试`
- 按钮：`重试`
- 判定：接口 reject/超时时出现；点击重试触发重新请求

### 2.2 分模块文案

1. 代理设置（general）
- 保存成功：`代理设置已保存`
- 校验失败：`请填写完整的代理地址和端口`
- 连接测试失败：`代理连接失败，请检查地址或凭证`
- 判定：
  - host/port 为空且 proxyType!=none -> 校验失败
  - 测试接口失败 -> 连接测试失败

2. 工作区设置（workspace）
- 空态：`暂无工作区`
- 辅助：`添加后可用于快速创建会话与任务`
- 错误：`工作区列表加载失败`
- 按钮：`重新加载`

3. MCP 设置（mcp）
- 空态：`暂无 MCP 服务`
- 辅助：`添加服务后可在会话中调用工具`
- 错误：`MCP 服务加载失败`
- 按钮：`重试加载`

4. 技能设置（skills）
- 空态：`暂无已安装技能`
- 辅助：`可从技能市场安装后使用`
- 错误：`技能列表加载失败`
- 按钮：`重新获取`

5. 日志设置（logs）
- 空态：`暂无日志记录`
- 辅助：`执行一次任务后可查看日志`
- 错误：`日志读取失败`
- 按钮：`重新读取`

## 3. Markdown 统一渲染验收标准（前端 + QA）

### 3.1 渲染链路统一（必须）

1. 统一组件：assistant 文本统一走 `react-markdown`
2. 插件统一：`remark-gfm` + `rehype-highlight`
3. 样式统一：统一使用 `markdown-body` 及其子样式类
4. 链接统一：外链必须 `target=_blank` 且 `rel=noopener noreferrer`

### 3.2 流式与完成态渲染规则（必须）

1. 流式输出中（`delta-*` 且 `isStreaming=true`）：
- 纯文本等宽渲染，不做 Markdown 解析

2. 流式结束后（`isStreaming=false`）：
- 同一消息必须转为 Markdown 渲染
- 即使 message id 仍是 `delta-*`，也不得继续以纯文本展示

### 3.3 元素级验收条目（可直接执行）

1. 标题
- 输入：`# H1`、`## H2`
- 预期：字号与粗细按样式分级，段前后间距正确

2. 行内代码与代码块
- 输入：`` `npm run dev` ``、```ts code fence
- 预期：
  - 行内代码使用 `markdown-inline-code`
  - 代码块使用 `markdown-code-block`，可横向滚动
  - 语法高亮生效（关键字颜色非纯文本）

3. 表格（GFM）
- 输入：标准 pipe 表格
- 预期：外层有 `markdown-table-wrapper`，小屏不撑破容器

4. 列表与引用
- 输入：有序/无序列表、blockquote
- 预期：缩进、行距、引用左边框样式一致

5. 链接
- 输入：`[OpenAI](https://openai.com)`
- 预期：新窗口打开，鼠标悬停有下划线反馈

6. 图片
- 输入：Markdown 图片或附件图
- 预期：最大宽度不超容器，圆角一致

### 3.4 Markdown 状态文案（补齐 loading/empty/error）

1. loading（消息流式中）
- 文案：`正在生成内容…`
- 判定：assistant 正在流式输出且文本暂未完成时显示

2. empty（assistant 内容为空）
- 文案：`模型未返回可显示内容`
- 操作：显示“复制原始消息”与“重试”入口（至少一个）
- 判定：assistant 消息最终内容为空字符串

3. error（渲染失败）
- 文案：`内容渲染失败，已切换为纯文本`
- 行为：自动降级纯文本，不阻断会话
- 判定：Markdown 渲染异常时触发降级与文案

## 4. 组件库对齐清单（交互设计输出）

1. `SettingsShellFullScreen`
- 职责：全屏容器 + Header + 左导航 + 内容区
- 必备状态：loading/empty/error/ready

2. `SettingsTabNav`
- 职责：分类导航，支持 badge 与错误点标记

3. `SettingSection`
- 职责：分组标题、描述、内容容器

4. `SettingSwitchRow`
- 职责：单行开关配置（即时保存）

5. `SettingFormRow`
- 职责：输入框 + 校验 + 保存按钮（显式提交）

6. `StateBanner`
- 职责：统一展示 `loading/empty/error` 文案与动作按钮

7. `MarkdownRenderer`
- 职责：统一 Markdown 渲染封装，屏蔽业务差异

8. `MarkdownFallbackNotice`
- 职责：渲染异常降级提醒（error 态）
