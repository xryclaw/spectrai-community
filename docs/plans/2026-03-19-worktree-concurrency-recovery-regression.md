# Worktree 并发隔离与失败恢复回归清单

## 1. 执行范围

本清单用于联调期阻断回归，覆盖以下高风险路径：

- A/B 会话同时创建 worktree
- 分支命名冲突
- 创建失败后重试
- 关闭开关后复用主工作区（非 worktree）
- M1-M4 强校验：并发唯一性、失败回滚无残留、SESSION_CREATE 元数据、enter_worktree 重入隔离

## 2. 执行前置

1. 执行环境检查：

```bash
bash scripts/worktree-preflight.sh
```

2. 准备测试输入（可复用）：

- 仓库路径：当前项目根目录
- 会话 A：`QA-WT-CONC-A`
- 会话 B：`QA-WT-CONC-B`
- 冲突分支名：`feat/qa-wt-conflict-fixed`
- 基线分支：当前 HEAD（若产品强制 main/master，则按产品规则）

## 3. 阻断级回归用例

| 用例ID | 场景 | 可复现步骤 | 预期结果 | 阻断级别 |
|---|---|---|---|---|
| CRR-001 | 并发创建 A/B worktree | 1) 打开两个新建会话窗口；2) 均保持 `使用 git worktree` 勾选；3) 同时点击创建；4) 在 A 修改 `qa/probe-a.txt` 但不提交；5) 在 B 执行状态检查 | A/B 均创建成功；A 未提交改动在 B 中不可见；A/B 分别绑定独立 workspace 与 branch | P0（隔离失效） |
| CRR-002 | A/B 同文件并行改动隔离 | 1) A/B 同时修改同一路径同一行（不合并）；2) 分别执行提交预览 | 两会话均可独立暂存与提交；不出现交叉覆盖；冲突仅允许在后续合并阶段出现 | P0（会话互相污染） |
| CRR-003 | 分支命名冲突 | 1) 会话 A 指定分支 `feat/qa-wt-conflict-fixed` 创建成功；2) 会话 B 使用同名分支创建；3) 观察系统处理 | 系统必须显式处理冲突（拒绝并提示 / 自动重命名并记录）；禁止静默覆盖已有分支 | P1（主链路中断或误覆盖） |
| CRR-004 | 创建失败后重试 | 1) 人为制造失败（目录占用/权限不足/锁冲突）；2) 触发创建失败；3) 恢复条件后点击重试 | 错误信息明确；重试可成功；失败残留可清理；无僵尸会话、无半初始化状态 | P1（不可恢复） |
| CRR-005 | 会话关闭后清理回收 | 1) 成功创建 worktree 会话；2) 关闭会话；3) 检查 worktree list 与目录回收状态 | 关闭后进入 cleanup，最终资源回收；若首轮失败，补偿任务可收敛 | P1（持续泄漏） |
| CRR-006 | 关闭开关复用主工作区 | 1) 新建会话取消 `使用 git worktree`；2) 创建会话并查看 workspace mode/branch 展示；3) 验证代码路径 | 会话按非 worktree 旧路径运行；展示为主工作区模式；无错误 fallback 红标 | P1（核心开关失效） |
| CRR-007 | migration 回滚可执行 | 1) 触发迁移执行场景；2) 按回滚入口/回退 runbook 执行回滚；3) 校验回滚后数据一致性与可启动性 | 回滚步骤可执行且可恢复到一致状态；无不可逆损坏 | P1（回滚不可执行） |
| M1 | 并发唯一性强校验 | 1) 同 repo 并发触发多次会话创建；2) 校验 worktree 路径与分支名；3) 检查是否复用同一工作目录 | 每个会话必须拥有唯一 worktreePath + branch；不得出现共享同一路径 | P0（并发唯一性失效） |
| M2 | 失败回滚无残留强校验 | 1) 注入创建失败（目录冲突/权限失败/锁冲突）；2) 触发回滚；3) 校验 .spectrai-worktrees、git worktree list、分支残留 | 失败后无悬挂 worktree、无多余分支、无半初始化记录 | P0（失败回滚残留） |
| M3 | SESSION_CREATE 返回工作目录元数据 | 1) 调用 SESSION_CREATE；2) 校验返回字段 | 返回中必须包含 worktreePath/worktreeBranch/workspaceMode（或等效字段）；与实际一致 | P1（元数据缺失/不一致） |
| M4 | enter_worktree 重入隔离强校验 | 1) 同会话重复调用 enter_worktree；2) 跨会话并发调用 enter_worktree；3) 对比返回路径与会话绑定关系 | 重入调用不得破坏已有绑定；跨会话不得指向同一隔离目录；元数据一致 | P0（重入破坏隔离） |

## 4. 每步输入/输出判定模板

### 4.1 并发创建（CRR-001）

- 输入：两个并行创建请求，均启用 worktree。
- 关键输出：
  - UI：A/B 会话分别显示不同 workspace 路径与 branch。
  - 后端日志：同 repo provision 受互斥控制，无竞争写损坏。
- 判定标准：
  - 通过：A/B 都 Ready，互不可见未提交改动。
  - 失败：任一会话读取到另一会话未提交改动，记 P0 阻断。

### 4.2 分支冲突（CRR-003）

- 输入：重复分支名 `feat/qa-wt-conflict-fixed`。
- 关键输出：冲突提示或自动重命名结果（需可追溯）。
- 判定标准：
  - 通过：无静默覆盖，用户可理解并继续。
  - 失败：覆盖原分支或错误无提示，记 P1 阻断。

### 4.3 失败重试（CRR-004）

- 输入：首次创建故障 + 恢复后重试。
- 关键输出：错误码、重试行为、残留清理状态。
- 判定标准：
  - 通过：重试成功且状态一致。
  - 失败：重试后仍卡死或遗留污染，记 P1 阻断。

### 4.4 关闭开关复用主工作区（CRR-006）

- 输入：关闭 worktree 开关的新建会话。
- 关键输出：workspace mode 显示主工作区，branch 与旧流程一致。
- 判定标准：
  - 通过：行为与历史非 worktree 路径一致。
  - 失败：仍强制创建 worktree 或状态显示错误，记 P1 阻断。

### 4.5 migration 回滚可执行（CRR-007）

- 输入：迁移后触发回滚演练（按系统回滚入口或 runbook）。
- 关键输出：回滚执行日志、回滚后启动结果、关键数据一致性校验。
- 判定标准：
  - 通过：回滚可执行且可恢复一致状态。
  - 失败：无回滚入口或回滚后状态不一致，记 P1 阻断。

### 4.6 M1-M4 执行口径（立即执行计划）

- 执行时机：前后端修复提交后第一轮回归优先执行 M1-M4，再执行 CRR 余项。
- 证据要求：每条至少 1 份终端日志 + 1 份接口/界面证据（字段截图或响应片段）。
- 结论规则：M1/M2/M4 任一失败直接判定 P0 阻断；M3 失败判定 P1 阻断。

## 5. 联调阈值升级规则（即时生效）

任一条件满足，QA 立即升级给 Leader：

1. 30 分钟内 `PROVISION_FAILED >= 3`
2. `CLEANUP_PENDING > 20`
3. fallback 使用率 `> 5%`
